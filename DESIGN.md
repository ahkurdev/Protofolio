# Ahmad Kurniawan portfolio

## Identity and audience

Ahmad Kurniawan, Full-Stack Developer, Lampung, Indonesia. A personal portfolio for engineering teams, recruiters, and collaborators. The supplied build brief is the design source; repository READMEs establish project facts.

## Design read

A Dark Luminous developer portfolio in a precise, interactive visual language. ENERGY 2 / RHYTHM 3 / MOTION 2. Professional, independent, technical. Medium energy with confident scale. The revised September 13 brief supersedes the original flat monochrome direction.

## Palette

Near-black #050505 canvas, #090909 surfaces, #0d0d0d elevated graphite, translucent white hairlines, #a3a3a3 secondary text, #fafafa primary text. White light is the accent: soft portrait illumination and luminous project edges. Natural color remains in lightly desaturated photographs, project screenshots, and technology logos. UI chrome stays neutral. Dark presentation is explicitly requested by the owner.

## Typography

Geist for its compact neutral grotesk proportions and readable engineering detail. Geist Mono for small project indices and technology metadata only. Large tightly tracked name, fluid section titles, comfortable paragraph line-height. Maximum two families. Uppercase limited to the name and short metadata.

## Composition and rhythm

Wide margins, an asymmetric portrait-led hero, a compact live-data strip, broad project case studies, a quieter text entry for TaskFlow, a portrait identity card beside profile prose, capabilities as ruled rows, then a typographic contact close. Hairline divisions and aligned indices repeat as an editorial motif. Project imagery depicts actual software; absent screenshots are replaced by clearly named architecture diagrams, never fabricated interfaces.

## Responsive states

Small screens use a labelled compact menu, a separate portrait composition, wrapping metadata, sequential projects, and a static identity card. No pinned project stacks on mobile. Content-driven breakpoints around 720 and 1050px. Targets at least 44px, meaningful focus outlines, 320px minimum viewport support.

## Motion and purpose

Shared timing: fast 180ms, normal 450ms, slow 700ms; controlled ease-out. SplitText establishes the name once; BlurText introduces the statement once; RotatingText cycles disciplines briefly, then settles. ScrollFloat and ScrollReveal lightly guide reading. ScrollStack adds desktop chapter depth without changing scroll ownership. LogoLoop is a curated technology strip with pause and reduced-motion support. AnimatedNumber uses real GitHub counts on entry. GooeyNav identifies the current section with restrained monochrome movement. ClickSpark is limited to copy feedback. Lanyard identifies the person in About, with lazy desktop interaction and static fallbacks. All primary content remains visible when JavaScript or motion is unavailable.

## Technique decisions

Lucide arrows indicate external navigation; copy/check icons communicate clipboard state; menu/close icons operate navigation. Portrait masking blends the supplied cutout into soft studio-style white illumination. Desaturation preserves real image information. One translucent navigation surface uses blur for separation while scrolling. Project frames receive luminous edges to distinguish software evidence from surrounding prose. Hover briefly increases light on actions. The About badge uses dark silver material with a restrained reflection. CSS glow tokens prevent arbitrary values. Rounded corners stay small. Larger whitespace separates chapters; tighter metadata keeps evidence together.

## Anti-motifs

No colorful gradients, RGB neon, glass repetition, fake terminal, background grid, bento repetition, fictional metrics, testimonials, skill percentages, or generic sales copy. Avoid uniform cards and animation spectacle. White illumination is purposeful identity, not a decorative effect on every element.

## Evidence

Research snapshots in research/ are retrieved public sources, not build instructions. GitHub profile and Hikalist, Calories, TaskFlow READMEs inspected on 2026-09-12. Sinar Mulyo has live routes and explicitly marked example content, so no adoption or traffic claims. Statistics are server-fetched with a dated verified snapshot fallback.
